# Facilities Project Tracker (standalone)

The same app as the claude.ai version, running on Firebase (sign-in, database, file storage) and any static host.

## How it fits together
- `public/index.html` is generated by `build.py` from `../project-tracker.html` (the claude.ai version). Edit that file, then run `python3 build.py`.
- `public/shim.js` answers the app's `claude.use(...)` calls with Firebase: email + password sign-in with email verification, Firestore, Storage, downloads.
- Access: the owner email (set in `config.js` and the rules) can change everything. Anyone whose email is on a contact (`access/{email}`) can sign in, read, register their own profile and ask questions. Everyone else sees "Almost there".
- `firestore.rules` / `storage.rules` are generated from the `.template` files.

## Setup
1. Firebase console: create a project, enable Authentication > Email/Password, create Firestore (production mode), register a Web app and copy its config into `firebase-config.json`.
2. `python3 tools/configure.py OWNER_EMAIL firebase-config.json` writes `public/config.js`, `firestore.rules`, `storage.rules`.
3. Paste `firestore.rules` into Firestore > Rules and publish (and `storage.rules` into Storage > Rules if Storage is enabled; Storage needs the Blaze plan).
4. Upload the `public/` folder to a static host (Netlify Drop, Firebase Hosting via `firebase deploy`, GitHub Pages...). Add the site's domain under Authentication > Settings > Authorized domains.
5. Owner opens the site, creates an account with the owner email, confirms it, fills the welcome form, then uses "Choose export file" with `data/export.json` to bring over the claude.ai data.
   (Alternative with a service account: `GOOGLE_APPLICATION_CREDENTIALS=key.json node tools/import.js data/export.json OWNER_EMAIL`.)

## Refreshing the export
Dump the claude.ai artifact's collections with ArtifactData (projects, projects/{id}/updates, contacts, groups, people, questions, files) into a folder, then `python3 tools/make_export.py <folder> data/export.json`.

## Testing locally
`npm install`, `python3 tools/configure.py clint@example.com demo-fb.json --emulators`, then
`npx firebase emulators:exec --only firestore,auth,storage,hosting --project demo-tracker "node tools/e2e.js"`.

## Update files (meeting notes → Apply updates)

Clint drops meeting notes in the project thread; Claude reads them and sends back a JSON file. In the tracker, **Apply updates** loads it, shows each change with a checkbox, and saves the ticked ones as project updates (marked `source: "meeting notes"`).

```json
{"kind": "siemonsma-updates", "source": "Weekly facilities meeting, Oct 5",
 "changes": [{"projectId": "imp02", "project": "Building I (Add a garage door)",
   "set": {"status": "On track", "phase": "Rough-In", "percent": 40, "priority": "High",
           "startDate": "2026-10-01", "dueDate": "2026-10-30",
           "nextMilestone": "Door install", "milestoneDate": "2026-10-20", "budget": 12000},
   "note": {"done": "...", "next": "...", "blockers": "..."},
   "why": "short quote from the notes"}]}
```

Every key under `set` and `note` is optional. Projects match by `projectId`, then by exact name. Status, phase and priority must be values the tracker already uses; anything else is shown to Clint as skipped.
